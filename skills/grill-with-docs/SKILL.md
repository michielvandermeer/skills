Bring the checkout up to date first — pull, with submodules — so the facts you declare and the files you edit are current.

Run a `/grilling` session, using the `/domain-modeling` skill. The glossary entries and ADRs that session produces are yours to write, in this session: `/domain-modeling` times the glossary entries and states an ADR as a declaration, and an ADR that waits for Spec time is written in the same turn as the Spec.

When the request asks for a `/prototype`, or a question turns out to need one, run it after the Frontier is empty and before the ending below; its verdict is the last set of declarations, and only a Spec that is written names its folder.

Once the Read-back is confirmed, take exactly one ending. The confirmed Read-back is the only test — a forecast in an earlier Round is not confirmation.

**Change to implement** — the settled design still names a change. Run `/to-spec`, then `/retro`. Leave an originating Issue or Idea in place so `/to-spec` can point it at the Spec. A mixed Read-back ("do not build X, do build Y") takes this ending for Y; X is Out of Scope on that Spec.

**Work we will not do** — the whole settled design names no change. Skip `/to-spec`. Delete an Issue or Idea this session started from when one exists; Ideas filed during the session for branches still wanted stay. Glossary entries already written stay; write no ADR that was waiting for Spec time. Say that you wrote no Spec because nothing will be built. Then run `/retro`.

## From a GitHub issue

A session that starts from a **GitHub issue** — a link, or a bare number for this checkout's repository — keeps its record on that issue: read [triage/GITHUB-ISSUE.md](../triage/GITHUB-ISSUE.md) before round 1. Every comment it posts starts with:

```
> *This was generated by AI during grilling.*
```

- Before round 1, check that this session can write to the repository's issues, push, and open pull requests. When one is missing, stop and say which.
- The issue's body and whole thread are the written brief D1 reads.
- A branch cut from scope but still wanted becomes a new GitHub issue in place of an Idea: the sections `/validate-spec` checks on an Idea, a link back to this issue, and no status label.
- **Change to implement**: `/to-spec` writes the Spec into the issue body, and the glossary, ADR, and Prototype edits go into the grilling draft it opens.
- **Work we will not do**: close the issue as not planned, with a comment saying why, and remove its status label. Glossary entries already written go into a grilling draft without `Closes`.
- A session stopped before the Frontier is empty posts every settled decision and unanswered Question as a comment, and the issue keeps `needs-grilling`.
