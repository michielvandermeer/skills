# Document types

A document no template shapes has one type. Two questions pick it: does it serve doing or understanding, and does it serve learning or work?

- **Tutorial** (doing, learning). Say what the reader will build. Every step produces a result they can see, and the text says what they should see. Explanation shrinks to one clause and a link. Write as "we", in commands: "First, run x. Now, open y."
- **How-to** (doing, work). Solve a problem a person has. Assume competence, give only the actions, and allow forks: "If you want x, do y." Name it by the task: "How to rotate the signing key".
- **Reference** (understanding, work). Only describe: facts, options, limits, and errors, stated with no hedging. Mirror the structure of the thing described, so code and docs can be read side by side.
- **Explanation** (understanding, learning). One bounded topic, anchored on a real why question: design decisions, history, constraints, alternatives. Opinion belongs here and nowhere else.

Keep the types apart. A reference table inside a tutorial, or an argument inside a how-to, goes to its own document with a link.
