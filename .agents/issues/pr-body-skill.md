# Decide whether to add a skill that shapes pull request bodies

Category: enhancement
Status: needs-grilling

## Problem

Upstream v1.3.0 added `pr`, a model-invoked skill that loads whenever the agent writes a pull request body. The body opens with the smallest visual that makes the change clear: pseudocode, a call tree, a file tree, a diagram, or a diff. Next comes before-and-after evidence that the change works. It ends with how risky the merge is: whether it can be undone easily, and how much breaks if it goes wrong. The summary visuals come from Dex Horthy's `show-me` skill.

No skill in this plugin writes a pull request. The implement commands never push or open one ([ADR-0028](../../docs/adr/0028-implement-never-leaves-the-repository.md)), so the user or the host writes every pull request body without guidance.

## Out of scope

- Having the implement commands open pull requests. ADR-0028 rules that out.

## Open questions

- Do the people using this plugin write pull request bodies through the agent often enough to need a skill?
- Copy upstream's template as it is, or adapt it to our plain-language standard and our Spec and Step vocabulary?
- Should the implement commands' final report reuse the same evidence and merge-risk sections?
