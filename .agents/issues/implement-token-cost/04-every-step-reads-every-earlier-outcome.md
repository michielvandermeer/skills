# Every Step reads the Outcome of every earlier Step

Category: enhancement
Status: needs-grilling
Spec: .agents/specs/implement-agents-start-smaller.md

## Problem

`/implement` tells each `skills:implementer` to read the `## Outcome` of every lower-numbered Step before it starts. By Step 20 that is about 20k tokens, on top of the full Spec (about 11k). The agent re-reads it on every turn, so the cost grows with the square of the Step count.

Proposed change: the Planner writes a `Depends on:` line in each Step file, and the Driving session passes only those Outcomes. Estimated saving: about 3% of total spend.

The full measurement is in commit `5d4d45e`, in the Issue this one was split from.

## Comments

**Why this status:** the change touches the Step format and an ADR, and a person has to decide how.

**What we know:** `skills/implement/SKILL.md` step 3 has the line "an instruction to read the `## Outcome` of every lower-numbered step file". ADR-0045 says the numbering is the dependency order, so Step files carry no `Blocked by:` line. A `Depends on:` line would be about context, not order, but it sits close to that decision.

**What is blocked:** these choices, for a `/grill-with-docs` session:

- Does `Depends on:` belong in the Step file format in `skills/implement/STEPS.md`?
- Can the Planner judge dependencies well enough? If it misses one, the Step agent lacks a fact it needs.
- Should the Driving session fall back to every Outcome when the line is missing?
- Does this need an ADR, or an amendment to ADR-0045?
