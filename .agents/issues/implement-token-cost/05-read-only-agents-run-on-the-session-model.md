# Read-only agents run on the session's model

Category: enhancement
Status: needs-grilling

## Problem

Reviewers and explore agents only read code. They still run on the session's model, which is Opus with the 1M context window. In 48 hours of transcripts (2026-09-24 to 2026-09-26), they cost $181: $100 for 93 per-Step and final reviews, and $81 for Explore and explorer walks.

Proposed change: run them on Sonnet. Estimated saving: about 5% of total spend, or more if the plan counts Sonnet against a separate limit.

The full measurement is in commit `5d4d45e`, in the Issue this one was split from.

## Comments

> *This was generated by AI during triage.*

**Why this status:** the change goes against decisions in force, so a person has to decide it.

**What we know:**

- `skills/code-review/SKILL.md` step 4 starts both reviewers "at this session's own model and effort".
- ADR-0049 keeps agents bound to a Spec on the session's model. One reason it gives is that no fallback is needed on a host with no Sonnet tier, because nothing names a model.
- ADR-0007 notes that a `model: sonnet` pin quietly upgrades anyone who started a Haiku session.
- `agents/explorer.md` pins only `effort: medium`. The built-in `Explore` agent cannot be pinned from this plugin.

**What is blocked:** these choices, for a `/grill-with-docs` session:

- Which agents move: the Spec reviewer, the Standards reviewer, `skills:explorer`, or some of them?
- Is a fixed `model: sonnet` pin acceptable, given the reasons in ADR-0049 and ADR-0007?
- Does this amend ADR-0049, or need a new ADR?
