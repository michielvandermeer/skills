# Speed up worktrees by cloning folders

Category: enhancement
Status: needs-grilling

Peter Steinberger wrote that OpenClaw's next release makes worktrees about 80% faster. It clones folders with copy-on-write on APFS, Btrfs, XFS, and ReFS. That also uses less disk. The seed asked whether `/implement`, `/implement-oneshot`, and `/prototype` can do the same.

Those skills create a worktree with `git worktree add`. Git shares the object store. It still writes a full working tree of tracked files. Ignored install trees such as `node_modules` are not copied. A prototype then installs dependencies from scratch.

I searched `CONTEXT.md`, [ADR-0014](../../../docs/adr/0014-implement-worktree-host-agnostic.md), [ADR-0031](../../../docs/adr/0031-implement-runs-ready-steps-in-parallel.md), and the three skills that run `git worktree add`. None of them clone a folder or share file data on copy.

The technique is real. The way we would use it is not settled. This plugin is prose a host agent follows. It cannot import OpenClaw's library. A host tool that creates the worktree and moves the session into it still wins. Each Step still gets its own worktree with `git worktree add`, so those copies would feel any clone path we add.

- Filesystems that cannot clone (ext4, NTFS, HFS+) keep a normal Git checkout.

- Decide what happens on a filesystem that cannot clone: skip, or copy install trees the slow way.
