# Decide whether the skills take their document paths from the repo

Category: enhancement
Status: needs-grilling

## Problem

Every skill that reads or writes a Spec, Idea, Issue, Prototype, or report names a fixed root path, such as `.agents/specs/<slug>.md` or `.agents/prototypes/<slug>/`. mvdmio-suite keeps these per app under `.agents/<app>/`. Its `.agents/refs/issue-tracker.md` tells each skill to put `<app>/` after `.agents/`. That works only when a skill happens to read that ref, and nothing in the skills tells them to.

The retro that found this suggested that each skill should take its paths from the repo's tracker ref.

The ref changes more than the folder. In mvdmio-suite an Issue is `.agents/<app>/issues/<slug>.md` with no `NN-` number. The ref also names commands this plugin does not have (`/idea`, `/plan`).

## Open questions

- Should the skills support a repo's own layout at all? [ADR-0001](../../../docs/adr/0001-fixed-local-issue-tracker.md) chose one fixed tracker with no per-repo setup. It names a per-repo `issue-tracker.md` as the setup layer it removed.
- If they should, which is it: a ref file every skill reads, or one built-in layout with a folder per context, keyed off `CONTEXT-MAP.md`?
- What is a context's folder when an app has no `CONTEXT.md`, as with `shared/` in mvdmio-suite?
- How does a skill find a slug it is handed when the path depends on the app?
