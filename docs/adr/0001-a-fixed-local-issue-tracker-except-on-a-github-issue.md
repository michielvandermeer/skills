# A fixed local issue tracker, except on a GitHub issue

Issues live as markdown files at `.agents/issues/<slug>/<NN>-<slug>.md`, with fixed `Status:` and `Category:` strings and no per-repo setup. Work that starts from a **GitHub issue** — a link, or a bare number for the checkout's own repository, handed to `/triage`, `/grill-with-docs`, or an implement command — keeps its triage result and its Spec on that issue instead, never in the repo. Local files for that work made a cloud agent commit them and open a pull request whose only job was to record triage, while the issue itself showed nothing. Every other seed — pasted text, pasted issue text included, a file, a local Issue, a Jewel ticket — keeps the local files.

On the issue, the reporter's text stays in the body until a Spec replaces the whole body; GitHub's edit history keeps the original. A result that waits goes in a comment, and every comment starts with the line marking it as generated by AI. Each ending sets one status label — `needs-info`, `needs-human`, `needs-grilling`, or `ready-for-agent` — in place of the last, and one category label, `bug` or `enhancement`. The names are fixed, and the skills create a missing status label. A waiting issue stays open. A Spec stays open until a pull request with `Closes #N` in its body is merged. Work we will not do is closed as not planned, or as completed when it is already built, and loses its status label.

## Considered Options

- **A tracker chosen per repo by a setup skill**, as Matt Pocock's skills do. Rejected: the seed already says where its work lives, so a repo would carry setup files for a choice nobody makes.
- **GitHub issues for every seed.** Rejected: a paste, a file, a local Issue, or a Jewel ticket has no GitHub issue to write to.
- **A Spec in the repo with a pointer on the issue.** Rejected: the Spec would again need a pull request whose only job is to record it.

## Consequences

- The skills use whatever GitHub access the session has. `/triage` checks it can write to the issues; `/grill-with-docs` checks issues, push, and pull-request rights before its first round; the implement commands check push and pull-request rights before they start. Each stops without them.
- Only `/triage`, `/grill-with-docs`, `/to-spec`, and the three implement commands take a GitHub issue. `/refine` still takes an Idea or a Jira ticket.
- A `docs/agents/issue-tracker.md`, `docs/agents/triage-labels.md`, or `docs/agents/domain.md` left in a consuming repo by a `setup-matt-pocock-skills` run is inert and safe to delete.
